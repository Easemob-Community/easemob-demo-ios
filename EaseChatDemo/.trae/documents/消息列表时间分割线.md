# 消息列表增加居中时间分割线（复用 AlertMessageCell）

## Context
聊天消息列表需要像主流 IM 一样，在消息之间按时间插入**居中显示的时间分割线**，避免所有时间都挤在每条消息旁边。用户明确要求复用 `AlertMessageCell` 来渲染这条分割线。

规则：
1. 当天消息：`18:29`
2. 昨天消息：`昨天 18:29`
3. 更早消息：`12月24日 18:29`
4. 相邻消息间隔 ≤ 5 分钟时不重复展示时间分割线（跨天时仍要展示）

## 实现方式
把"时间分割线"作为一条带标记的 `MessageEntity` 直接注入到 `MessageListView.messages` 数组中，由现有的 `registerMessageCell` 里 `EaseChatUIKit_alert_message` 分支（即 `ChatAlertCell`）渲染，无需改 cell 注册/复用逻辑。因为现有更新路径全部通过 `firstIndex(where: { messageId == })` 定位真实消息，分割线实体的 messageId 为空、不会被误匹配，数组下标 == 表格行号，table 渲染与滚动均正确。

## 改动点

### 1. `MessageEntity.swift`（Uikit/.../Chat/ViewModel/MessageEntity.swift）
- 新增全局高度常量：`public var timeDividerHeight = CGFloat(28)`（放在 `alertHeight` 附近）。
- 新增标志与文本：
  - `public var isTimeDivider = false`
  - `public var dividerText = ""`
- 在 `cellHeight()` 开头加：`if self.isTimeDivider { return timeDividerHeight }`
- 新增生成分割线实体的便捷方法，例如：
  ```
  public static func timeDivider(timestamp: Int64, text: String) -> MessageEntity
  ```
  内部创建空 `MessageEntity`，设置 `isTimeDivider = true`、`dividerText = text`，并给 `message.timestamp` 赋值。
- 新增格式化方法（供分割线文案用），例如 `open func timeDividerText() -> String`：
  - 用 `Date(timeIntervalSince1970: timestamp/1000)` 与当前 `Date()` 判定：同一天返回 `HH:mm`；差一天返回 `昨天 HH:mm`；否则返回 `M月d日 HH:mm`。
  - 时间格式化复用 [DateExtension.swift](file:///Users/xiaofeng/Desktop/Project/Easemob-Community/easemob-demo-ios/EaseChatDemo/Uikit/Sources/EaseChatUIKit/Classes/UI/Core/Extension/DateExtension.swift) 的 `dateString(_:)`（支持自定义格式串），日期差用 `Calendar`/`compareDays()`。

### 2. `AlertMessageCell.swift`（目标文件）
- **去掉 alert 提醒消息自身的时间**：在 `refresh(entity:)` 中，对非分割线的 alert 消息只显示 `content`，隐藏 `time`（不再 `time.text = entity.message.showDate`）。
- 时间展示统一交给分割线：`refresh(entity:)` 中当 `entity.isTimeDivider == true` 时：
  - 隐藏 `content`；
  - `time.isHidden = false`，`time.text = entity.dividerText`，并让 `time` 内容垂直居中（沿用居中样式，调整 frame/center）。
- 在 `layoutSubviews` 中按"是否分割线"微调 `time` 的位置，保证居中；alert 消息的 `time` 保持隐藏。

### 3. `MessageListView.swift`（Uikit/.../Chat/Views/MessageListView.swift）
在三个写入入口注入分割线（新增私有辅助方法 `shouldInsertTimeDivider(before:previousTimestamp:)`：首条消息、或与上一条间隔 >5 分钟、或数个不同日历日则插入）：

- `refreshMessages(messages:)`：构造 `messages` 时，逐个消息计算是否在其前插入 `timeDivider` 实体，再 `reloadData()`。
- `insertMessages(messages:)`（上拉加载更多，头部插入）：对传入的这批消息计算"批内 + 批末到现有头部"的分割线后插入到 0 位置。
- `showMessage(message:)` 追加新消息时：比较新消息与上一条（最后一条非分割线）真实消息时间戳，决定是否先 `append(timeDivider)` 再 append 真实消息。

> 说明：`insertMessages` / `showMessage` 中"上一条真实消息"取 `messages` 里最后一个非 `isTimeDivider` 元素的时间；删除/撤回等按 messageId 定位的路径天然跳过分割线，无需额外改动。历史/话题页共用 `refreshMessages`/`showMessage`，会一并生效。

## 验证
- 在模拟器/真机跑 `MessageListController`，制造相邻间隔不同（同 <5 分钟、同 >5 分钟、跨 昨天、跨更早）的连续消息，确认：
  - 分割线居中显示，文案符合三条规则；
  - ≤5 分钟的两条消息之间不出现第二条分割线；
  - 列表正常上下滚动、发消息自动滚到底部、删除/撤回消息后分割线无残留错位。
- 检查 alert（话题 @ 提示）消息样式不被破坏。
